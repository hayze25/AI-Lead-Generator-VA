AI Business Assistant
A small business assistant project I built to experiment with using AI for handling customer inquiries and basic lead management.

The idea is to take incoming messages, categorize them, identify possible sales leads, and help prepare replies. It also has a React dashboard for reviewing inquiries and managing leads. For email automation, I connected the API to n8n.

This is an MVP and still has limitations. It is mainly a project for exploring how an ASP.NET Core backend, an AI service, a frontend dashboard, and workflow automation can work together.
Tech stack
- Backend: ASP.NET Core Web API (.NET 10)
- Database: SQL Server with Entity Framework Core
- Frontend: React and Vite
- Automation: n8n
- AI: LLM API through an ILlmService interface
- Local environment: Docker Compose
How it works
1. A customer inquiry is submitted through the dashboard or the website form webhook in n8n.
2. The API saves the inquiry and sends its content to the AI service for triage.
3. The AI returns a category, sentiment, urgency, summary, and lead score.
4. Sales and partnership inquiries can be added to the lead pipeline. Existing leads are matched by email.
5. A user can generate a reply draft, edit it, and send it from the dashboard.
6. n8n handles email delivery and checks for follow-ups that are due.
Replies generated by the AI are drafts. A user needs to review and send them from the dashboard. Scheduled follow-up emails are sent by n8n when they become due.
Main features
Inquiry management
- Submit inquiries from the dashboard.
- Receive inquiries through an n8n website form webhook.
- View and filter inquiries by status and category.
- Run AI triage again when needed.
AI triage and reply drafts
The AI classifies inquiries into Sales, Support, Billing, Partnership, Spam, or Other. It also provides a sentiment, urgency level, short summary, and lead score.

Reply drafts use the business profile, including its description, tone, FAQs, and pricing information. I can also provide extra instructions when generating a draft.
Lead management
- Sales and partnership inquiries can create or update a lead.
- Leads are matched using their email address.
- Follow-ups can be scheduled and cancelled.
- Leads can be moved through the pipeline, such as Won or Lost.
Email automation
I used n8n for the email-related workflows instead of putting all of that logic directly in the API.

The API sends email requests to n8n. Another workflow checks for follow-ups every 15 minutes and reports back to the API after sending them.
Business profile
Each business can set its name and upload a logo. The profile information is also used when generating AI replies.

Running locally
Requirements
- Docker Desktop
- Node.js 20 or newer
- npm
1. Configure environment variables
Copy the example environment file:
cp .env.example .env
Update the values in .env. At minimum, set the SQL Server password, dashboard credentials, JWT key, and automation API key.

For AI features, add your LLM API key and configure the model and base URL. If no API key is provided, the application uses its demo mode.
2. Start the backend services
From the project root:
docker compose up --build
This starts SQL Server, the ASP.NET Core API, and n8n.

The API is available at:
http://localhost:5080
n8n is available at:
http://localhost:5678
3. Start the frontend
Open another terminal:
cd frontend
npm install
npm run dev
The dashboard should be available at:
http://localhost:5173
Sign in using the admin credentials configured in .env. The application also has an account registration option if registration is enabled.
Demo mode
The application can run without an LLM API key. In this mode, it uses basic keyword-based rules for triage and template-based reply drafts.

This makes it possible to try the main inquiry and lead-management flow without configuring an AI provider. AI-generated triage and drafts require a valid API key.
n8n configuration
After starting Docker Compose:
1. Open http://localhost:5678 and create the n8n owner account.
2. Import the workflow files from the n8n/ folder.
3. Configure SMTP credentials in the email nodes.
4. Make sure the API key in the n8n HTTP Request nodes matches AUTOMATION_API_KEY in .env.
5. Activate the workflows.
The included workflows are:
Workflow	Trigger	Purpose
Send email	Webhook	Receives an email request from the API and sends it through SMTP.
Send due follow-ups	Every 15 minutes	Gets due follow-ups from the API, sends the emails, and reports successful sends.
Website form to inquiry	Webhook	Receives website form data and submits it to the API.


For a quick test, you can submit a sample inquiry to the website form webhook:
curl -X POST http://localhost:5678/webhook/website-lead \
  -H "Content-Type: application/json" \
  -d '{"name":"Ana Reyes","email":"ana@example.com","subject":"Pricing","message":"How much for 20 units? Need them by Friday."}'
Configuration
The application reads configuration from environment variables or appsettings.json. For nested settings in environment variables, use double underscores (__).
Setting	Description
ConnectionStrings__Default	SQL Server connection string
Auth__Username	Admin username
Auth__Password	Admin password
Auth__AllowRegistration	Enables or disables new account registration
Auth__JwtKey	Key used to sign authentication tokens
Llm__ApiKey	API key for the selected LLM provider
Llm__Model	Model name
Llm__BaseUrl	LLM API base URL
Automation__ApiKey	Shared key used by the API and n8n
N8n__BaseUrl	n8n URL used by the API
N8n__DryRun	Logs email requests instead of sending them to n8n
Database__AutoCreate	Creates the database schema on startup
Cors__Origins__0	Allowed frontend origin


The project can create its database schema on startup. Alternatively, set Database__AutoCreate=false and run database/schema.sql manually. Use one approach for a database, not both.

The AI integration is handled through ILlmService, so the provider implementation can be changed without changing the inquiry-management code.

Accounts and data separation
The project supports separate business accounts. Registration creates a business profile and an account for its owner. Inquiries, leads, replies, follow-ups, and business settings are associated with that business.

The business ID is taken from the authenticated user's token rather than accepting it from the dashboard request. Registration can be disabled using AUTH_ALLOW_REGISTRATION=false.

The website form workflow currently sends inquiries to the original business by default. To route a form to another business, the workflow's API request can include that business's ID.
A few implementation decisions
- Save inquiries before calling the AI. If the AI service is unavailable, the inquiry is still stored and can be triaged again later.
- Keep reply sending under user control. The AI prepares a draft, but the user reviews and sends it.
- Use n8n for email delivery. This keeps the email workflow separate from the main API.
- Share inquiry logic. Dashboard submissions and n8n submissions use the same inquiry service.
- Keep the AI provider replaceable. The API uses the ILlmService interface rather than depending directly on one provider.
Current limitations
This is still an MVP. There are things I would improve before using it with real businesses:
- Registration does not include email verification or password recovery.
- Follow-up emails are sent automatically when due. There is not yet an approval step for each scheduled follow-up.
- The public website form webhook needs additional protection, such as rate limiting or another verification mechanism.
- If an n8n batch fails after sending some emails, some follow-ups may be retried and sent again.
- All businesses currently share the configured LLM API key and SMTP account.
- Each business has one user account. Team members and role-based permissions are not implemented.
- Inquiry messages may contain personal information, so a proper retention and deletion policy is needed before production use.
For local development, the Development configuration includes a default login and dry-run email behavior. Do not use development credentials or settings on a public deployment. Use HTTPS and replace all default secrets before exposing the application.
This project is a work in progress. The main goal was to build an end-to-end example of inquiry handling, AI-assisted responses, lead tracking, and workflow automation using technologies I have been working with.
